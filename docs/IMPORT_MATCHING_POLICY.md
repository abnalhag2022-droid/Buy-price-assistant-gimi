# سياسة مطابقة الأصناف عند الاستيراد

> تنطبق على الإصدار 1.5.0 وما بعده. الكود: `lib/data/spreadsheet_exchange.dart`
> (`exactKey`، `looseKey`، `analyze`)، والاختبارات: `test/spreadsheet_exchange_test.dart`.

## المبدأ

**لا يُضاف سجل سعر إلى صنف موجود إلا إذا كان التطابق مؤكدًا.** كل تشابه غير مؤكد يُعرض على المستخدم ليقرر، ولا تتغير بيانات أي صنف موجود بسبب الاستيراد.

السبب: في الإصدار 1.4.0 كانت المطابقة تتجاهل ترتيب الكلمات، فاعتُبر «كابل 2 خط 4 ملم» و«كابل 4 خط 2 ملم» صنفًا واحدًا، ودخلت أسعار صنف في سجل صنف آخر.

## توحيد الاسم قبل المقارنة

يُوحَّد الاسم والوحدة بالقواعد نفسها المستخدمة في البحث (`normalizeForSearch`):

| يُوحَّد | لا يُوحَّد |
|---|---|
| الحروف الكبيرة والصغيرة اللاتينية | ترتيب الكلمات |
| التطويل (ـ) والتشكيل | الأرقام وقيمها: 2 ≠ 4 |
| أ إ آ ٱ ← ا، ؤ ← و، ئ ى ← ي | التاء المربوطة والهاء (ة ≠ ه) |
| الأرقام العربية والفارسية ← لاتينية (٤ = 4) | الكلمات الزائدة أو الناقصة |
| المسافات المتعددة ← مسافة واحدة | الوحدة (متر ≠ لفة) |

المفتاح الدقيق `exactKey` = الاسم الموحَّد + الوحدة الموحَّدة، **بترتيب الكلمات نفسه**.
المفتاح المرن `looseKey` = الكلمات نفسها مرتبة أبجديًا + الوحدة؛ يُستخدم **لاكتشاف** الأسماء المتشابهة فقط، ولا يربط شيئًا تلقائيًا.

## القرار لكل صنف في الملف

تُجمع صفوف الملف التي لها المفتاح الدقيق نفسه والكود نفسه في «مجموعة». الصفوف بلا كود تنضم إلى مجموعة الاسم نفسه إذا كان لها كود واحد فقط.

| الحالة في قاعدة البيانات | النتيجة |
|---|---|
| للمجموعة كود، ويطابقه صنف **واحد** نشط له **الاسم الدقيق نفسه** | مطابقة تلقائية |
| للمجموعة كود يطابق صنفًا باسم مختلف، أو عدة أصناف، أو صنفًا مؤرشفًا | **يحتاج قرارًا** |
| لا كود مطابق، ويوجد صنف **واحد** نشط بالاسم الدقيق نفسه، ولا تعارض في الكود | مطابقة تلقائية |
| الاسم نفسه لكن الكودان مختلفان | **يحتاج قرارًا** |
| عدة أصناف بالاسم نفسه، أو صنف مؤرشف بالاسم نفسه | **يحتاج قرارًا** |
| الكلمات نفسها بترتيب مختلف (مثل 2 خط 4 / 4 خط 2) | **يحتاج قرارًا** |
| لا شيء مما سبق | صنف جديد |

في حالة «يحتاج قرارًا» تعرض المعاينة كل صنف مرشح مع سبب الترشيح (الكود نفسه، الاسم نفسه، الكلمات نفسها بترتيب مختلف) والحقول المختلفة (الاسم، الوحدة، الكود، التصنيف، العلامة). يختار المستخدم:

- **ربط** بأحد المرشحين المعروضين فقط (لا يمكن الربط بصنف لم يُعرض)؛ وإذا كان مؤرشفًا تُلغى أرشفته ويُذكر ذلك قبل التأكيد.
- **إنشاء صنف جديد** بالاسم الوارد في الملف.
- **تخطي** صفوف هذا الصنف.

يبقى زر الاستيراد معطلًا حتى يُتخذ قرار لكل صنف ملتبس. يوجد خياران جماعيان: «إنشاء الكل كأصناف جديدة» و«تخطي الكل».

## ما لا يفعله الاستيراد أبدًا

- لا يغيّر اسم صنف موجود أو كوده أو تصنيفه أو علامته أو ملاحظاته.
- لا يحذف ولا يعدّل أي سجل سعر موجود.
- لا يحوّل العملات.
- لا يدمج أسماء متشابهة داخل الملف نفسه: تبقى أصنافًا منفصلة مع تنبيه.

## السجلات المكررة

سجل السعر مكرر إذا طابق سجلًا موجودًا للصنف الهدف (أو صفًا آخر في الملف) في: النوع، والتاريخ، والسعر، والعملة، والكمية، والمورد/العميل، ورقم الفاتورة، والملاحظات. **تُتخطى المكررات افتراضيًا**، فإعادة استيراد الملف نفسه لا تضيف شيئًا. يمكن إضافتها عمدًا بمفتاح في المعاينة.

## الأمان والتراجع

1. التحليل والمعاينة لا يكتبان شيئًا.
2. قبل الكتابة تُحفظ نسخة أمان تلقائية من كل البيانات.
3. الكتابة في معاملة واحدة؛ يُعاد تحليل الملف داخلها، وإذا تغيرت الأصناف منذ المعاينة يتوقف الاستيراد دون كتابة شيء.
4. كل استيراد يحمل معرّف دفعة؛ «التراجع» يحذف سجلات تلك الدفعة فقط، والأصناف التي أنشأتها إن لم تُضف لها سجلات أخرى، ويعيد أرشفة ما ألغت أرشفته.

## English summary

Rows are linked to an existing product automatically only when (a) the code identifies exactly one active product with the same normalized name and unit, or (b) exactly one active product has the same normalized name — **in the same word order** — and unit, with no conflicting code. Reordered words, same code with another name, same name with another code, several same-name products and archived matches all require an explicit decision (link to a listed candidate, create new, or skip). Normalization unifies case, diacritics, alef/hamza forms and Arabic/Persian digits; it never ignores word order, numbers, extra words, taa marbuta vs. haa, or the unit. Existing products and records are never modified, duplicates are skipped by default, a safety snapshot is taken first, the import is atomic and re-validated, and every import can be undone.
